ADR-0001: Application shell

Why Tauri 2, and the replaceable-shell rule.

Status

Accepted · living document · supersedes nothing · superseded by nothing.

Context

LinkFYR ships a privileged Rust networking service (linkfyrd) and needs an unprivileged front end for it on Windows, macOS and Linux, with mobile companions later on. The shell must never leak its frameworks into the trust boundary: the GUI is a client of the service, and swapping it out must not touch the crates that do real work.

The candidate shells were Electron, Tauri 2 and a pure native toolkit per platform.

Decision

  • Tauri 2 over Electron: the webview is the system's own (smaller footprint, no bundled Chromium runtime), the Rust side integrates directly with the workspace crates, and the security model (explicit capability grants, no Node in-process) fits the unprivileged-client rule.
  • The replaceable-shell rule: all Tauri types live in apps/desktop only. Every feature the GUI offers goes through linkfyr-ipc, the typed, versioned API. The CLI (linkfyr) and the tray speak the same contract. The shell is disposable by design — replacing Tauri with Qt, GTK or anything native is a UI project, never an engine project.
  • Mobile companions (Tauri 2 app for Android/iOS) reuse the same IPC contract, so platform work stays additive.

Consequences

  • Benefit: One desktop codebase across three OSes with system webviews and no Chromium tax.
  • Benefit: IPC versioning gives the CLI and the tray a stable surface; shells can lag or lead the engine independently.
  • Trade-off:System webview differences are real; the UI renders a capability matrix instead of faking parity (see platform support).
  • Trade-off:Tauri 2 mobile still inherits platform review processes; not a shortcut around store policies.
